# Lightning 建图错位/重影排查（2026-10-27）

本次排查保持运行中的 WSL 建图进程不变，不发运动/存图服务，不替换正在加载的动态库。
用户反馈停车后仍有重影。只读采集的 `/map` 栅格本身也存在边缘重复，
因此既要检查 TF/扫描显示，也要检查地图生成。

## 已确认的代码问题

1. **地图与机器人位姿不是同一个坐标系。** 栅格、保存点云使用关键帧
   `pose_opt`，旧 `/tracked_pose` 却将未经回环修正的 LIO 位姿直接标记为 `map`。
   本次日志内关键帧优化前后位置差最大约 2.20 m；这是同一帧的两个位置差，
   不等于所有墙面都错位 2.20 m。该差异在停车后也会保留。
2. **位姿时间戳错误。** 旧消息用发布时的 `node_->now()` 给历史扫描的位姿盖时间戳，
   `tracked_pose_tf_node` 随后在这个新时刻取里程计，运动时会引入额外错位。
   处理未成功的扫描此前也会重复发布旧状态。
3. **栅格绘制存在并发一致性缺口。** 同一关键帧在地图扩展、障碍物命中和
   空闲射线绘制时重复读取可被回环线程改动的位姿；前后台绘图共用
   `floor_coeffs_`；ROS 地图转换也可能与地图写入/替换并发。
   这些是明确的数据竞争风险，但不能仅凭代码就断言它们解释了全部地图重影。

## 本次修复

- `/tracked_pose` 使用 `T_map_lio = T_map_kf_opt * inverse(T_lio_kf)`，
  再乘当前 LIO 位姿；不强行改写 LIO 内部状态。
- 消息时间戳使用扫描状态的实际测量时间；失败/未初始化状态不再发布。
- 每次栅格更新冻结关键帧位姿，保证命中点、空闲射线和边界使用同一姿态。
- 串行保护前后台共享的地面估计工作区；地图转换/回调与地图写入和替换互斥。
- 不凭此次排查盲改 NDT 阈值、噪声协方差、地图分辨率或点云滤波参数。

只读采样中 `/map`、`/tracked_pose`、合流点云、IMU、里程计各有一个发布源。
前后雷达时间戳的最近样本差中位数为 0 ms；外参为前/后 X=±0.36 m、Z=0.10 m，
后雷达 yaw≈π，IMU 与 base_link 重合，与当前配置一致。
采集期间车辆有运动；观察到的最近样本时差最大值不能直接视为同步器配对误差，
也不能把不同时间的点云与位姿当作配准精度基准。

采样产物保存在 `runtime/diagnostics/lightning-20261027/`：
`report.json`、`log_summary.json`、`map.png`、`snapshot.npz`。
这些属于本地诊断数据，不随镜像打包。

## 如何生效与验收

当前建图进程仍是旧版本，源码修复不会热更新到当前地图。
先用现有流程保存当前成果，再正常停止 bridge 和其托管的 Lightning，之后执行：

```bash
bash scripts/build_lightning.sh
source install/setup.bash
# 按原参数重新启动 bridge，并从前端开始一轮新建图
```

不要在旧 Lightning 仍运行时覆盖其共享库。Docker 部署则在建图结束后重建 bridge
镜像并重建容器。建议用新的地图名对比，保留旧成果；重新加载旧地图不会自动消除
它已累计的栅格误差。

验收应覆盖：停车时扫描与地图边缘对齐、直行/转弯时的时间一致性、回到起点触发
回环后的重绘，以及保存后的 PGM/PCD。此次完成的是代码修复和离线回归/语法检查，
尚未重启活动建图进程验证地图改善，不能宣称全部重影已消失。
若新一轮仍有结构重影，再针对原始点云和关键帧检查配准漂移、误回环与场景退化。

## 同日补充：前后与横移、不旋转仍然重影

三舵轮横移本身不违反当前 Lightning 的输入假设：LIO 前端直接使用点云和 IMU，
没有将其强制建模为只能沿车头前进的差速底盘。少旋转不能修复错误回环或绘图问题。
继续分析本轮日志与实现后，还确认以下问题：

- **异常回环边实际仍参与求解。** 日志曾记录 `loop outliers: 156/774`。
  回环模块启用增量模式，但 MIAO 的 `InitFromLast` 只追加边，不移除已被标记为
  level 1 的旧活动边；剔除后也没有立即重优化，地图会继续携带异常约束造成的偏移。
- **回环目标混入近期轨迹。** 候选最小间隔为 20 个关键帧，而构造历史子地图时
  取候选前后 40 帧，可能包含当前帧及其近期邻居，形成自匹配和虚高的匹配分值。
- **地图坐标未固定。** 相对位姿图缺少首帧锚点，世界原点/朝向存在自由度；
  原实现还只按分值接收 NDT，没有拒绝不收敛或非有限的匹配结果。

本次追加修复：回环图每次重建当前 level-0 活动约束（仍使用稀疏求解），
异常边剔除后再优化；保留有效边的鲁棒核以便后续继续检查；固定首帧；
从历史子地图中排除当前帧和最小时间间隔内的邻帧，拒绝无效 NDT 结果。
不改变三舵轮运动学，不禁止横移，也没有盲目调高匹配分数阈值。

`test_loop_validation.cc` 使用**前进→横移→后退→横移，全程零旋转**的合成轨迹，
注入错误平移回环，验证异常约束真正退出活动集合、重优化恢复轨迹、图增长后旧异常边
不会重新生效，以及地图首帧保持固定。该回归由 `scripts/check_lightning_mapping.py` 运行。

最初检查时安装中的 `liblightning.libs.so` 仍为 2026-10-26 版本；当时上述源码修复尚未进入
运行程序。原建图已保存为 `map1027` 并转为定位，本次没有启动新建图或重写该地图。
保存图上的重影不能作为“修复后仍失败”的证据；需要正常停止加载 Lightning 的进程，
重编译后再用相同平移路线、新地图名做实际对比。
